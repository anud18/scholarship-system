## 四、設定差異

### 4.1 部署設定（`docker-compose.prod.yml`）

| 設定項目 | 舊版 | 新版 | 差異說明 |
| --- | --- | --- | --- |
| `PII_ENCRYPTION_KEYS` | 無 | 新增（必填） | 個資加密金鑰，部署時由金鑰管理機制注入 |
| `PII_ENCRYPTION_ACTIVE_VERSION` | 無 | `v1` | 支援金鑰輪替 |
| `SUPER_ADMIN_NYCU_ID` | 未設定 | 新增 | 指定經 Portal SSO 登入後具最高管理權限之帳號 |
| `BASE_URL` | 未設定（沿用預設 localhost） | `https://${DOMAIN}` | 修正檔案下載連結、信件連結產生錯誤網址之問題 |
| `MINIO_BUCKET` | `MINIO_BUCKET_NAME`（無效設定） | `MINIO_BUCKET` | 修正舊版設定名稱錯誤導致實際採用預設值之問題 |
| `SSL_CERT_DIR` | 憑證路徑寫死於 repo | 可指定主機任意路徑 | 私鑰不必存放於版本庫，符合金鑰保管要求 |
| Redis 記憶體上限 | 未設定 | `--maxmemory` + `allkeys-lru` | 避免快取無限成長耗盡記憶體 |
| 容器映像版本 | 監控元件使用 `latest` | 全部釘選明確版本（Alloy `v1.11.0`、node-exporter `v1.10.1`、cadvisor `v0.55.1`） | 確保部署可重現、避免非預期升版 |
| cadvisor 資源限制 | 無 | `mem_limit: 256m` + healthcheck | 避免監控元件異常影響正式服務 |
| logrotate | 直接讀取掛載設定檔（權限問題致輪替失效） | 於容器內重建 root 權限副本後執行 | 修正日誌未輪替之問題 |

### 4.2 Nginx 設定（`nginx.prod.conf`）

| 設定項目 | 舊版 | 新版 |
| --- | --- | --- |
| `Strict-Transport-Security` | 未完整套用 | `max-age=31536000; includeSubDomains; preload` |
| `Cross-Origin-Opener-Policy` | 無 | `same-origin` |
| `Cross-Origin-Embedder-Policy` | 無 | `require-corp` |
| `Cross-Origin-Resource-Policy` | 無 | `same-origin` |
| `Permissions-Policy` | 無 | 停用 camera／microphone／geolocation／payment／USB 等 20 餘項瀏覽器功能 |
| `Referrer-Policy` | 無 | `strict-origin-when-cross-origin` |
| `X-Content-Type-Options` | 部分套用 | 全站套用 `nosniff` |
| `X-Frame-Options` | 部分套用 | 全站套用（`DENY`／`SAMEORIGIN`） |
| 伺服器資訊隱藏 | 無 | `proxy_hide_header Server`、`X-Powered-By` |
| 速率限制 | 無 | `limit_req` 分區限流，逾量回應 429 |
| 上傳大小限制 | 未明確設定 | `client_max_body_size 11M` |
| 靜態資源快取 | 未設定 | `Cache-Control: public, max-age=31536000, immutable` |

> 補充：新版並修正舊版 Nginx 設定中「子區塊宣告 `add_header` 會導致繼承之安全標頭全數失效」之結構性問題，確保所有路徑（含 `/api/`、靜態資源）皆實際輸出完整安全標頭。
